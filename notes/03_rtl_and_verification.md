# Step 3 — RTL and verification log

## Decisions made by the owner, in order (2026-10-27/28)

1. Step 2: array **4 × 10** (option B), **2x2 tiles**, **50 MHz** sign-off clock.
2. Accumulator: **24-bit internal, saturating**, exact for K ≤ 65,535 (|acc| ≤ 128·K), with
   `sat16(acc >>> shift)` readout (5-bit shift, floor semantics, the FPGA's `sat16_shift` contract), or
   plain 16-bit saturating if 24-bit does not fit the 2x2 comfortably. Local Yosys estimate: 38,623 vs
   34,548 µm² (+11.8 %) with identical readout logic.
3. The real flow is ~1.55× my local estimate (notes/04). 24-bit 4×10 was predicted at ~85 % of the core, so
   the rule gave plain 16-bit. But even 16-bit 4×10 was ~73 % full, so the owner re-decided: **4 × 5 with the
   faithful 24-bit + shift datapath in 2x2**, accepted only at ≤ ~60 % utilisation with timing closed and no
   unresolved ss slew violations. Otherwise fall back to 4×10 in 3x2 (420 €).
4. 4×5 met utilisation (57.7 %) and timing (+5.7 ns at ss), but not zero slew. After one final
   over-constrained attempt (not clean), the owner's rule signed off **V7**: residual 1 data net, 5 ps over
   at nom ss, documented in notes/04.

**Shipped design:** `tt_um_msohair_tmac`, ROWS = 4, COLS = 5, ACC_W = 24, 2x2 tiles, BIST signature 0xA97E.
The 4×10 versions remain in git (`acc24-shift-ref` tag, `eval/4x10-acc24-3x2` branch) for the larger
multi-tile chip.

## Bugs found, and what each one taught

1. **SPI rate (spec bug).** MISO moves ~3 clk after an SCK fall, and the TT mux adds up to ~20 ns. At
   f_clk/8 the master would sample it as it changes. Spec is now **f_SCK ≤ f_clk/16**.
2. **Testbench: cocotb deferred writes.** Two read-modify-writes of `ui_in` in one timestep both read the
   stale value. The second undid the first, so SCK stuck high and every byte read 0xFF. Fix: a Python shadow
   register. This is a testbench bug, not RTL, but it made 9/9 tests fail, so the RTL was never trusted until
   it was explained.
3. **Shared loop variables (synthesis-only bug).** `integer i`/`r` reused across `always` blocks simulates
   fine and is accepted by Vivado. Yosys treats it as one variable with multiple drivers, and LibreLane
   stopped with "34 Yosys check errors". Fix: one loop variable per block. Local synthesis now runs
   `check -assert`, so this class of error fails on the PC, not in CI.
4. **CLEAR did not clear ILLEGAL** (doc/RTL mismatch), found while writing the model.
5. **Gate-level sampling (practice design).** Sampling at `ReadOnly()` right after the edge passes RTL and fails
   GL (unit-delay cells). All TMAC tests drive and sample on falling edges.
6. **A live status flag that cost four barrel shifters.** "Would any row clamp at the current shift?" needs
   a shifter per row. Replaced by a sticky flag set by the shared readout shifter.
7. **BIST signature assumption.** I expected the 16-bit fallback to keep the 24-bit signature. It didn't: the
   fold XORs in the sign-extension bits. The signature is always regenerated by the model, never reasoned.
8. **Timing fixes driven by sign-off** (notes/04): registered decoder input, pipelined dot products, reset
   synchroniser.

## Results (shipped 4×5 design)

- RTL: **9/9 pass** (`test_internal_saturation` alone is ~13,200 SPI transactions, ~2 min).
- Gate level, on the signed-off netlist (local, `TMAC_GL_SLOW=1`): **9/9 pass**, including the 24-bit
  internal-saturation test (10 min). CI `gl_test` also passes (it skips that one test for time).
- Mutation testing **on the shipped RTL: 8 injected bugs, 8 caught**, each with a specific bit-exact
  message:

  | mutant | caught by | message |
  |---|---|---|
  | decoder ±1 code swap | test_decoder_exhaustive | `byte 0: codes 0x0155 want 0x3ff` |
  | logical instead of arithmetic shift | test_shift_floor_semantics | `shift 1: [32767, 32767, 2, 32767]` |
  | missing +1 carry-ins of negated terms | test_random_matvec | `raw acc [-128, 0, 126, -129] != model [-127, 1, 128, -128]` |
  | wrap instead of clamp | test_internal_saturation | `raw acc [-8386961, …] != model [8388607, …]` |
  | LOAD_AC never computes | test_streamed_matvec | `raw acc [0, 0, 0, 0] != model [-448, …]` |
  | BIST pipeline wait removed | test_bist | `BIST (opcode) failed` |
  | reset synchroniser disabled | test_reset_state | X on outputs (ValueError) |
  | sticky RSAT never set | test_readout_saturation | `status 0x81 != 0x83` |

  Earlier versions (4×10, 16-bit, and the reverted V8 overflow test) had their own batches: 9 more mutants,
  all caught.
- Local synthesis: `check -assert` clean, 0 problems.
